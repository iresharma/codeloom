The repeated smoke failures after the watchdog/budget fixes had two distinct, unrelated causes, both now fixed and confirmed by `railway-smoke-paths-retry` (2/2 arms passed, $0.2078 for that retry; $0.578 cumulative smoke spend). First, Engine's tester sub-agent always calls a fixed cheap model (`anthropic/claude-haiku-4.5`) for its own role regardless of the study's frozen generator; the broker rejected that outright, and the benchmark's own status-override logic then turned a successfully completed coding task into a false `agent_crash`. The broker now accepts a small per-model allowlist (`secondary_models` in `configs/core.yaml`) with its own pricing for the admission reservation; real billing still comes from the provider's reported usage cost either way. Second, that tester sub-agent always adds a test when the repo already has tests, by design; the `dev-smoke-python` task's `allowed_paths` only listed `tinydb/table.py`, so any coding system with normal test-writing discipline would fail `disallowed_edit` there regardless of correctness. `allowed_paths` now also lists `tests/test_tables.py`. The tester's own prompt and per-run task text were separately hardened to scope every edit to the files the coder actually changed, so it still never touches unrelated tests.

One Railway-sandbox retry also hit a `transport_error` mid-request (an unconfirmed OpenRouter-side disconnect), which the campaign ledger correctly flagged as an unknown bill and used to fail-closed on all further admission until reconciled. The owner confirmed a transport error of this kind is never billed and authorized settling it at $0 going forward without asking each time, rather than treating it as the full conservative reservation.
